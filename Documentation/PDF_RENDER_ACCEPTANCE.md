# Portable PDF rendering acceptance

The renderer is a prerequisite for portable PDF preservation checks and page
previews, not a substitute for graph/geometry checks. These requirements come from
`Sources/FileformCore/PDFStructuralFingerprint.swift` and
`Sources/FileformCore/PDFCompositionBackend.swift`.

## Required behavior

- Run parsing/rendering outside Electron and preserve independent CLI operation.
- Do not execute document JavaScript, launch actions, access links or enable XFA
  scripting merely to render. Protected/signed/interactive cases keep their
  explicit eligibility gates.
- Inspect every relevant page's geometry, rotation and text. Keep exact qpdf graph
  evidence as a separate check for lossless operations.
- Render a bounded bitmap on a white background. The reference fingerprint caps
  scale at 2 pixels/point and the longest edge at 2048; composition also performs a
  64×64 decode check. Define the new renderer's box/rotation/UserUnit behavior
  explicitly before comparing outputs.
- Compare before/after using the same renderer/version/options. Cross-renderer
  pixel equality is not assumed: antialiasing and fonts can differ.
- Never allocate from unchecked dimensions/stride; bound pages, input bytes,
  decoded pixels, output bytes and execution time. Cancellation must reap the
  helper and clean only its owned staging files.
- Keep raw bitmaps native. Return bounded metadata/hashes or an owned preview
  artifact, with explicit lifetime and cleanup.

## Fixture coverage before release

1. Filled vector shapes and text with a standard font.
2. Multiple page sizes and order; inherited boxes, negative/nonzero origins,
   rotation and UserUnit; crops and local bleed/trim/art boxes.
3. Embedded raster images, transparency, masks and color profiles.
4. Object-stream/flate rewrites: graph, text, geometry and rendered pixels remain
   stable. Deliberate drawing/text/image changes must fail preservation checks.
5. Missing fonts/resources, malformed streams, oversized dimensions/page counts,
   encrypted input and preservation-sensitive features fail predictably.
6. Mac arm64/x64 and Windows x64 helper builds and runtime fixtures; record manual
   Windows GUI gaps separately from automated native tests.

The qpdf two-page fixture is already generated by `tests/smoke-pdf.py` under the
engine crate. Add richer rendering fixtures without importing user documents.
PDFium dependency provenance, licenses and exact build configuration must be
reviewed before production integration. Full process containment and signed pack
integration remain release gates even when basic rendering tests pass.
