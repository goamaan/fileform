# PDF image optimization

`pdf.optimize` explicitly permits lossy JPEG image recompression and optional intrinsic image resampling. It retains every page, text, vector graphics, page geometry and scalar Info/XMP document metadata. The existing [PDF compress/fit conversion route](PDF-optimization.md) remains structural and lossless by default. Neither route rasterizes whole pages.

```sh
fileform pdf optimize input.pdf --output smaller.pdf --quality 0.8 --minimum-quality 0.5 --pdf-pack ./PDFPack --json
fileform pdf optimize input.pdf --output email.pdf --maximum-image-dimension 1920 --max-bytes 1000000 --pdf-pack ./PDFPack --json
fileform pdf optimize input.pdf --output planned.pdf --dry-run --json
```

`--maximum-image-dimension` is a longest-edge bound in **pixels**, not DPI. It is optional: omitted means no resampling. Images are never enlarged; proportional dimensions round down, with at least one pixel per edge. Page placement, clipping, boxes and rotation stay unchanged. `--max-bytes` selects fit; omission selects compression. Fit checks the complete PDF byte count after each verified attempt. Compression publishes only a smaller file; otherwise it returns `not_smaller` with no artifact.

The public operation is `.pdfOptimize(parameters: PDFOptimizationParameters)`, ID `pdf.optimize`, with one PDF asset, PDF file output and `.allowDeclaredLosses` fidelity. Parameters contain `goal` (`compress` or `fit`), `quality` (default 0.8), `minimumQuality` (default 0.5), optional `maximumImageDimension` and optional `maximumBytes`. Quality values must be finite and within 0.05–1, with floor no higher than initial quality. A positive byte limit is required only for fit. Pixel bounds are 1–16384. `transform` and portable `setup create/apply` retain exactly these parameters; generic conversion options are not repurposed.

Only 8-bit DeviceRGB and DeviceGray image XObjects with supported sample filters or a single DCT JPEG filter are recompressed. Resource traversal includes inherited/indirect resources, nested Forms and shared objects, once per original object/generation. Unused resource images can be included. Inline image instructions remain unchanged in their original content streams. Supported sample filters are Flate, ASCII85, ASCIIHex and RunLength without nontrivial predictor/decode parameters. Images with custom Decode arrays, explicit or soft masks, mask reuse, embedded-mask semantics, alternates, unsupported filters, complex/ICC color spaces, JPEG ICC profiles or unsupported JPEG orientation/sample interpretation remain unchanged with explicit candidate reasons. Alpha and profiles are never silently discarded. Rewritten JPEG descriptive metadata is not retained; PDF Info/XMP is retained. No claim is made to preserve signature validity, provide PDF/A, sanitize a document or redact content.

Fit uses at most six evenly spaced encoder-quality values, including the exact requested floor. Each attempt decodes the **original** image stream and applies the same explicit pixel bound; it never feeds a previous JPEG attempt into the next. It stops at the first verified candidate within the exact byte target. A fixed quality uses one attempt, as does a document with no eligible images. Failure returns `target_unmet`; no PDF is published, no pages are dropped and the floor is never lowered. The floor constrains the ImageIO JPEG encoder setting, not a perceptual score or a guarantee that the requested byte count is achievable. Output size need not be monotonic in quality.

Optional `pdfOptimization` plan/result details contain `PDFOptimizationImageCandidate` entries (`objectNumber`, `generation`, original/output width and height, `skipReason`), eligible/rewrite and resampling counts, attempted quality values and the selected quality. Plans carry empty attempts and no selected quality. `FileformError.pdfOptimization` supplies attempts and candidate details on target miss, with no selected quality. A not-smaller result describes its verified discarded candidate, not a published output.

The verified qpdf pack performs targeted `--update-from-json` stream replacement using private JPEG data files, followed by lossless stream/object compression. Before atomic publication, a bounded qpdf JSON snapshot of every **reachable** object and generalized-decoded stream is compared with the exact expected graph after replacing only eligible image streams and their width/height/filter/decode-parameter keys. This checks font dictionaries/programs, vector/Form content, resources, metadata and unsupported image bytes, not just page text. References are canonicalized by deterministic traversal, so object-number changes are allowed. Computed stream lengths, trailer ID/Size/Prev/XRefStm and explicitly typed XRef trailer transport keys are excluded. Remaining stream filters/data and semantic dictionary fields must match. Unreachable objects may be removed by structural rewriting.

A separate isolated CoreGraphics/PDFKit worker independently compares all page text, decoded page content, five boxes, rotations, page count and Info/XMP metadata. Whole-page raster hashes are deliberately not compared for equality after lossy image changes. Every replacement JPEG is fully decoded in the worker, with source dimensions checked **before decoding**, output dimensions/components/container checked after encoding, and its exact verified bytes included in the expected PDF graph. That graph also proves that every encoded replacement, including its encoding and dimensions, is the image installed into the PDF.

Both routes currently reject encrypted, signed, interactive, annotated/form, outlined, tagged/optional-content and other unsupported complex documents. This route requires the same verified PDF pack and isolated worker as structural optimization. No additional dependencies are introduced. Source/candidate bounds are 512 MiB, document bounds are 1000 pages, graph metadata is 32 MiB/100000 objects, and proof JSON (including generalized-decoded/base64 stream data) is limited to 128 MiB. There are at most 1000 unique image candidates, 16384 pixels per edge/64 million pixels per image and 512 MiB cumulative supported RGBA-equivalent sample bytes. A source encoded JPEG is at most 256 MiB; cumulative replacement JPEG bytes are at most 128 MiB. Each process and worker has bounded time/output, cancellation and private scratch cleanup. Plans preflight supported image encodings into private scratch and verify the source fits the graph-proof budget; they publish nothing.

Original identity and SHA-256 are checked during planning and after every execution attempt. Existing destinations, source paths, hard links and aliases are protected by the shared exclusive atomic output transaction; cancellation or failure cleans scratch. Execution rebuilds eligibility from the source rather than trusting serialized plan warnings or details.

`PDFLossyOptimizationTests` cover complete document retention, RGB/gray resampling, unsupported masks/profiles, exact floor-derived byte targets, original-based retries, target misses, graph tampering, cancellation, aliases, source changes and recipe/result compatibility. `python3 Tools/smoke-pdf-image-optimization.py --work <new-directory>` retains real CLI evidence and a source-owned synthetic continuous-tone landscape PDF with text, vectors, a nested Form, metadata, distinct boxes/rotations and an unsupported CMYK resource. This fixture models photographic image compression without including third-party photography.
